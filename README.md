# beekeepingFrontend

Вітрина маркетплейсу бджолиної продукції. Next.js 16 (App Router) + TypeScript +
Tailwind + Zustand + TanStack Query.

## Запуск

```bash
cp .env.example .env.local     # NEXT_PUBLIC_API_URL
npm install
npm run dev                    # http://localhost:3001
```

Потрібен запущений бекенд на порту 3000.

## Типи API

```bash
npm run api:types              # бекенд має бути піднятий
```

`lib/api/schema.d.ts` генерується зі Swagger бекенда. Руками не редагується.
Якщо бекенд змінив контракт, це видно як помилка типів тут, а не як зламана
сторінка в проді.

## Тести

```bash
npm run e2e        # потрібні піднятий бекенд і `npm run dev`
```

Playwright ганяє критерій запуску як тест: незнайома людина знаходить товар,
кладе в кошик, реєструється, оформлює замовлення і бачить його в себе. Плюс
два випадки, які мовчки ламаються: гуртовий покупець бачить свою ціну на тій
самій сторінці, і сесія переживає перезавантаження вкладки.

## Що де лежить

```
app/                    сторінки (за замовчуванням серверні компоненти)
components/             клієнтські острівці
lib/api/client.ts       браузерний клієнт: токен, мовчазне поновлення, повтор 401
lib/api/server.ts       читання для SSR — без токена, гостьові ціни
lib/auth/store.ts       сесія; access-токен лише в памʼяті
lib/cart/store.ts       кошик — лише кількості, ніколи не ціни
```

## Три правила, які тут тримають усе

**Фронтенд не рахує ціни.** Ціна залежить від ролі покупця та кількості, і знає
про це лише сервер. Змінилась кількість — питаємо API заново. У кошику
зберігаються `productId` і `qty`; ціна, покладена в localStorage, — це застаріла
ціна на момент оформлення.

**Access-токен живе лише в памʼяті.** Після перезавантаження вкладки він
зникає навмисно, а `POST /auth/refresh` з httpOnly-кукою повертає новий. Тому
XSS не має звідки його вкрасти. Паралельні 401 діляться одним запитом на
поновлення — інакше пʼять одночасних запитів проротували б токен пʼять разів і
взаємно його знеціли.

**Каталог рендериться на сервері.** Це єдиний безкоштовний канал трафіку, тому
сторінки товарів статичні, з canonical і Open Graph. Пошуковий робот — це
гість, і бачить роздрібну ціну; свою ціну гуртовий покупець отримує довантаженням
на клієнті через той самий ендпоінт.
